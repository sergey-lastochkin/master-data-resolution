# Дубли контрагентов и номенклатуры в 1С

[![CI](https://github.com/sergey-lastochkin/master-data-resolution/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/sergey-lastochkin/master-data-resolution/actions/workflows/ci.yml)

Ищу дубли среди контрагентов и товаров, выгруженных из 1С или соседних систем, и решаю, что склеить, а что нет. Если сравнивать просто по названию после чистки, получаются ложные склейки: два разных «Ромашка ООО» становятся одним. А если сравнивать каждую запись с каждой, на десятке тысяч записей это уже квадрат, никто не дождётся.

Поэтому записи сначала раскладываются по корзинам по нескольким ключам (нормализованное имя, ИНН, артикул и так далее), и сравниваются только те, кто попал в одну корзину. Разные ИНН или банковские реквизиты, одинаковый артикул при разных брендах - это жёсткий конфликт, такие записи не склеятся ни при каком похожем названии. Эмбеддинги для точных ИНН и артикулов я специально не использую. Если человек однажды сказал «это разные», это запоминается и больше не предлагается. При склейке по цепочке (А похож на Б, Б похож на В) перед объединением группа проверяется на конфликты внутри, чтобы А и В не склеились через посредника. А из каких полей собирать итоговую карточку, решает происхождение значения: проверенное значение важнее нового, но непроверенного.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python scripts/benchmark.py --records 10000
.venv/bin/python -m pytest -q
```

Бенчмарк на 10 000 записей считает precision, recall, F1, точность авто-склеек, долю ручной проверки и ложных склеек. Тесты проверяют нормализацию, корзины, точные совпадения, конфликты по ИНН и брендам, память отказов, повторные и конфликтующие сопоставления, сборку итоговой карточки и защиту от склейки через посредника. CI ещё гоняет `ruff` и `compileall`, только на синтетике, к 1С не подключается.

Важно: бенчмарк синтетический и простой, его цифры нельзя выдавать за качество на боевых данных. Память решений и сопоставлений живёт в процессе, интерфейса проверки и журнала аудита нет. Пороги и правила сборки карточки надо подбирать под конкретные данные. `bsl/MasterDataMapping.bsl` показывает, как это подключить к конфигурации, в 1С я его не запускал.
